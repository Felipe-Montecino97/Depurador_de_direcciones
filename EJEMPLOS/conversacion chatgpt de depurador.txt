Primer script: /api/generate
import requests

URL = "http://192.168.1.7:11434/api/generate"

payload = {
    "model": "llama3.1:8b",
    "prompt": "Explica qué es GenAI en 3 líneas",
    "stream": False
}

response = requests.post(URL, json=payload)

data = response.json()

print("\nRespuesta del modelo:\n")
print(data["response"])

Este script hace una petición directa al modelo usando el endpoint:

/api/generate

Ese endpoint se usa cuando quieres enviar un prompt simple al modelo.

Qué hace cada parte
URL
URL = "http://192.168.1.7:11434/api/generate"

Define la dirección donde está escuchando Ollama.

192.168.1.7 es la IP del servidor donde corre Ollama.
11434 es el puerto de Ollama.
/api/generate es el endpoint para generación de texto simple.
Payload
payload = {
    "model": "llama3.1:8b",
    "prompt": "Explica qué es GenAI en 3 líneas",
    "stream": False
}

Este es el cuerpo de la petición.

"model" indica qué modelo quieres usar.
"prompt" es la pregunta o instrucción que envías.
"stream": False significa que quieres recibir la respuesta completa de una vez.

Si stream fuera True, Ollama iría devolviendo la respuesta por partes, palabra por palabra o fragmento por fragmento.

Petición HTTP
response = requests.post(URL, json=payload)

Esto envía una petición POST a Ollama con el payload en formato JSON.

Conversión de respuesta
data = response.json()

Convierte la respuesta de Ollama a un diccionario Python.

La respuesta suele venir con una estructura parecida a esta:

{
    "model": "llama3.1:8b",
    "created_at": "...",
    "response": "GenAI es...",
    "done": True
}
Imprimir respuesta
print(data["response"])

Aquí muestras solo el texto generado por el modelo.

Este script usa el endpoint:

/api/chat

Este endpoint es mejor cuando quieres trabajar en formato conversación, parecido a ChatGPT.

Diferencia entre /api/generate y /api/chat

La diferencia principal es esta:

Endpoint	Uso principal	Formato
/api/generate	Prompt simple	"prompt": "texto"
/api/chat	Conversaciones con roles	"messages": [...]
Qué son los roles

En /api/chat, usas mensajes con roles:

"messages": [
    {
        "role": "system",
        "content": "Eres un arquitecto empresarial experto en SAP y GenAI."
    },
    {
        "role": "user",
        "content": "Qué ventajas tiene RAG híbrido?"
    }
]
system
{
    "role": "system",
    "content": "Eres un arquitecto empresarial experto en SAP y GenAI."
}

Este mensaje define el comportamiento del modelo.

Es como decirle:

Responde desde el punto de vista de un arquitecto empresarial experto en SAP y GenAI.

Esto condiciona el estilo, profundidad y enfoque de la respuesta.

user
{
    "role": "user",
    "content": "Qué ventajas tiene RAG híbrido?"
}

Este es el mensaje del usuario, o sea, la pregunta real.

Respuesta del endpoint /api/chat

La respuesta de /api/chat normalmente viene así:

{
    "model": "llama3.1:8b",
    "created_at": "...",
    "message": {
        "role": "assistant",
        "content": "Un RAG híbrido tiene varias ventajas..."
    },
    "done": True
}

Por eso imprimes:

print(data["message"]["content"])

En cambio, en /api/generate imprimías:

print(data["response"])

Porque la estructura de respuesta es distinta.

import requests

URL = "http://192.168.1.7:11434/api/chat"

payload = {
    "model": "llama3.1:8b",
    "messages": [
        {
            "role": "system",
            "content": "Eres un arquitecto empresarial experto en SAP y GenAI."
        },
        {
            "role": "user",
            "content": "Qué ventajas tiene RAG híbrido?"
        }
    ],
    "stream": False
}

try:
    response = requests.post(URL, json=payload, timeout=60)
    response.raise_for_status()

    data = response.json()

    print("\nRespuesta:\n")
    print(data["message"]["content"])

except requests.exceptions.ConnectionError:
    print("Error: no se pudo conectar con Ollama. Revisa la IP, el puerto y si Ollama está corriendo.")

except requests.exceptions.Timeout:
    print("Error: la petición tardó demasiado tiempo.")

except requests.exceptions.HTTPError as e:
    print("Error HTTP:", e)

except KeyError:
    print("Error: la respuesta no tiene la estructura esperada.")
    print(response.text)

Código base para leer Excel y usar Ollama

Este sería un ejemplo inicial bastante útil:

import pandas as pd
import requests
import json

OLLAMA_URL = "http://192.168.1.7:11434/api/chat"
MODEL = "llama3.1:8b"

ARCHIVO_ENTRADA = "direcciones.xlsx"
ARCHIVO_SALIDA = "direcciones_depuradas.xlsx"

df = pd.read_excel(ARCHIVO_ENTRADA)

# Ajusta estos nombres según tu Excel real
COLUMNA_ID = "RUT"
COLUMNA_NOMBRE = "Nombre"
COLUMNA_DIRECCION = "Direccion"


def limpiar_texto(valor):
    if pd.isna(valor):
        return ""
    texto = str(valor).strip()
    texto = " ".join(texto.split())
    return texto


def depurar_direcciones_con_ia(rut, nombre, direcciones):
    direcciones_limpias = [d for d in direcciones if d]

    if len(direcciones_limpias) == 0:
        return {
            "direccion_final": "",
            "confianza": "baja",
            "motivo": "No hay direcciones disponibles.",
            "direcciones_descartadas": []
        }

    if len(set(direcciones_limpias)) == 1:
        return {
            "direccion_final": direcciones_limpias[0],
            "confianza": "alta",
            "motivo": "Todas las direcciones son iguales.",
            "direcciones_descartadas": []
        }

    lista_direcciones = "\n".join(
        [f"{i+1}. {direccion}" for i, direccion in enumerate(direcciones_limpias)]
    )

    prompt_usuario = f"""
Persona:
RUT: {rut}
Nombre: {nombre}

Direcciones encontradas:
{lista_direcciones}

Debes devolver exclusivamente un JSON válido con esta estructura:
{{
  "direccion_final": "...",
  "confianza": "alta/media/baja",
  "motivo": "...",
  "direcciones_descartadas": [...]
}}
"""

    payload = {
        "model": MODEL,
        "messages": [
            {
                "role": "system",
                "content": """
Eres un sistema experto en depuración de direcciones chilenas.

Tu tarea es comparar direcciones posiblemente repetidas de una misma persona.

Reglas:
1. Selecciona la dirección más completa.
2. Si varias direcciones aportan información complementaria, consolídalas.
3. No inventes comuna, ciudad, número, departamento ni referencias.
4. Conserva datos como departamento, block, torre, villa, población, comuna y ciudad.
5. Si no puedes decidir claramente, usa confianza baja.
6. Devuelve exclusivamente JSON válido, sin explicaciones fuera del JSON.
"""
            },
            {
                "role": "user",
                "content": prompt_usuario
            }
        ],
        "stream": False
    }

    response = requests.post(OLLAMA_URL, json=payload, timeout=120)
    response.raise_for_status()

    data = response.json()
    contenido = data["message"]["content"]

    try:
        return json.loads(contenido)
    except json.JSONDecodeError:
        return {
            "direccion_final": "",
            "confianza": "baja",
            "motivo": "El modelo no devolvió JSON válido.",
            "respuesta_modelo": contenido,
            "direcciones_descartadas": []
        }


# Limpieza inicial
df[COLUMNA_DIRECCION] = df[COLUMNA_DIRECCION].apply(limpiar_texto)

resultados = []

for rut, grupo in df.groupby(COLUMNA_ID):
    nombre = grupo[COLUMNA_NOMBRE].iloc[0]
    direcciones = grupo[COLUMNA_DIRECCION].dropna().unique().tolist()

    resultado_ia = depurar_direcciones_con_ia(rut, nombre, direcciones)

    resultados.append({
        "RUT": rut,
        "Nombre": nombre,
        "Direccion_Depurada": resultado_ia.get("direccion_final", ""),
        "Confianza": resultado_ia.get("confianza", ""),
        "Motivo": resultado_ia.get("motivo", ""),
        "Cantidad_Direcciones_Originales": len(direcciones),
        "Direcciones_Originales": " | ".join(direcciones)
    })

df_salida = pd.DataFrame(resultados)
df_salida.to_excel(ARCHIVO_SALIDA, index=False)

print("Archivo generado:", ARCHIVO_SALIDA)

Recomendación importante

No uses IA para todo desde el principio. Usa esta lógica:

Si hay 1 dirección → conservar
Si hay varias idénticas → conservar una
Si hay varias parecidas → usar IA
Si hay varias totalmente distintas → marcar para revisión manual

Esto evita errores y hace el proceso más rápido.

Ejemplo de salida útil

La columna Confianza es clave, porque después puedes filtrar:

alta: aceptar automáticamente,
media: revisar si quieres,
baja: revisión manual obligatoria.
